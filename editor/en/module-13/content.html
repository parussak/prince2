Before Zosia got the green light to spend PLN 500,000. PLN, PixelBite Games carried out the **Starting up a project (SU)** process. A short **Project Brief** was created. Artur (the executive) checked whether the game made sense at all.

Only after the decision of the Project Board in the **Directing a project (DP)** process, Zosia entered the **Initiating a project (IP)** process, where she created full **Project Initiation Documentation (PID)** and carefully planned the first stage of implementation.

🔄 SU vs IP Process Comparison

Characteristic Starting up a project (SU) Initiating a project (IP)
When does it occur? Pre-project (before the initiation stage) In the first management stage (Initiation Stage)
Main goal Is the project justified and worth initiating? How exactly to organize and carry out the project?
Main product Project Brief Project Initiation Documentation (PID)
Time horizon Very short (a few days/weeks) A high-level project plan and management arrangements; the next stage plan is detailed at the stage boundary

In PRINCE2, there are at least **TWO management stages**: the Initiation Stage (where the IP process takes place) and at least one Execution Stage!

Additional textbook-aligned explanation

Starting up and initiating: distinct authorizations

Starting up a project checks whether there is a worthwhile, viable basis for initiating. The project mandate triggers a project brief and an initiation stage plan; the project board decides whether to authorize initiation. In initiating a project, the project manager develops the project initiation documentation (PID), including the business case, a high-level project plan, management approaches and project controls. The project board then decides whether to authorize the project. An initiation authorization is not approval of the whole project.

Plan detail at the stage boundary

The project plan gives a high-level view of the whole investment. The next delivery stage is planned in sufficient detail before it starts, normally at the previous stage boundary. The stage plan permits delegated day-to-day control; any exception plan needs the relevant authority’s approval. In SnakeBite, Artur evaluates the business case and PID before authorizing delivery, while Zosia later develops detailed plans for the following stage.

Chapter 16: Controlling a stage and managing product delivery

Purpose, decisions and SnakeBite scenario

Controlling a stage (chapter 16) lets the project manager assign work, monitor delivery, handle issues and risks, report progress and take corrective action within stage tolerance. Managing product delivery (chapter 17) is the team manager’s matching process: accept a work package, execute it and hand over the completed products. A team may use iterative delivery, but agreed products, quality criteria and tolerances still govern control.

SnakeBite example: Zosia authorizes Tomek’s ranking API work package with a product description and agreed time, cost and quality constraints. Tomek checks capacity before accepting it, coordinates specialist work and reports weekly through checkpoint reports. If his forecast exceeds work package tolerance, he notifies Zosia. Zosia can correct a problem within stage tolerance. If the stage forecast crosses its limit, she sends an exception report to the project board. After quality checks, Tomek notifies Zosia and hands over the products.

Key concepts and management products

Responsibilities: the project manager authorizes work packages and controls the stage; the team manager accepts and delivers them. Products and reports: work package description sets deliverables and controls; product descriptions set quality criteria; checkpoint reports go from team manager to project manager; highlight reports go from project manager to project board. Issue and risk registers keep assessed matters visible. A forecast beyond delegated tolerance leads to escalation at the relevant level.

Project manager versus team manager?

The project manager controls the stage; the team manager accepts, executes and delivers a work package.

What is a work package description?

The agreed specialist products, constraints and controls for a team’s assignment.

Which report does the team manager send?

Checkpoint report to the project manager.

Which report does the project manager send periodically?

Highlight report to the project board.

What if work package tolerance is forecast to be breached?

The team manager escalates to the project manager.

What if stage tolerance is forecast to be breached?

The project manager escalates to the board through an exception report.

Additional textbook-aligned explanation

Controlling a stage: project manager

The project manager authorizes work packages, reviews their status, captures and examines issues and risks, reports stage progress with highlight reports and takes corrective action within delegated stage tolerances. An expected breach of stage tolerance is explained in an exception report to the project board. The board makes stage decisions but does not assign individual specialist tasks in the normal course of delivery.

Managing product delivery: team manager

The team manager agrees the work package with the project manager, accepts it, organizes and executes the specialist work, reports progress in checkpoint reports and hands over completed products. The agreed work package description specifies products, quality requirements, reporting arrangements and any constraints or tolerance. If work package tolerance is forecast to be exceeded, the team manager informs the project manager, who considers the stage impact.

SnakeBite delivery loop

Zosia authorizes Tomek’s ranking API work package. Tomek reviews its acceptance criteria and dependencies, coordinates the build and records quality checks. He sends checkpoint reports and warns Zosia about a forecast package delay. When the tested API meets its criteria he delivers it to Zosia. She updates stage status, reports to the board and escalates if the stage forecast breaches tolerance.
